# Nesting

You will address nested objects and arrays by dotted path without extra setup.

## Nested objects

`resolveFieldDef` walks nested `elementFields`:

```tsx title="examples/nested-form.tsx"
<SmartField name="name" />
<SmartField name="address.street" />
<SmartField name="address.city" />
<SmartField name="address.zip" />
```

Schema in `examples/src/examples/nested-form.tsx`. Each segment steps into `elementFields`; unknown segments throw with available-field hints.

## Arrays

Array children resolve by explicit index only:

```tsx title="examples/array-form.tsx"
<SmartFieldArray name="tasks">
  {({ append, fields, move, remove, update }) => (
    <>
      {fields.map((row, index) => (
        <div key={row.id}>
          <SmartField name={`tasks.${index}.title`} />
          <SmartField name={`tasks.${index}.hours`} />
        </div>
      ))}
      <button type="button" onClick={() => append({ hours: 0, title: "" })}>
        Add task
      </button>
    </>
  )}
</SmartFieldArray>
```

| Path | How it resolves |
|---|---|
| `tasks.0.title` | Numeric segment into `kind === "array"` steps into `elementDef`, then `elementFields` |
| `tags.0` | Primitive `elementDef` directly (`z.array(z.string())` yields a `string` elementDef) |

Index-less `arr.city` is ambiguous (which row?) and throws — always use `arr.0.city`.

`SmartFieldArray` is a thin wrapper over RHF `useFieldArray`. The factory-bound version requires `<Form>` context (throws outside it) and validates `name` resolves to an `array` kind.

Render props:

| Prop | Meaning |
|---|---|
| `fields` | Current rows (`FieldArrayRow[]` — row values plus RHF stable `id` for `key`) |
| `append` | `(value: Record<string, unknown>) => void` — pass an explicit row value |
| `remove` | `(index: number) => void` |
| `update` | `(index: number, value: Record<string, unknown>) => void` |
| `move` | `(from: number, to: number) => void` |

Props are `{ name: string; children: (props) => ReactNode }`.

## Strict paths

`resolveFieldDef(fieldMap, name)` throws `createFormError` on empty names, empty segments (`"addr..city"`, leading/trailing dots), unknown roots, and unknown segments. Numeric keys on non-arrays look up literally.

Missing-field policy is `onMissingField` (`"throw"` default, `"warn"` renders `null` with a dev warning). Production always warns + renders `null`.

## Nested forms are not supported

Nested objects are supported. Sub-forms with an independent submit/validation lifecycle (separate `useForm` / `<Form>` inside another `<Form>`) are not — one `FormInstance` per form tree.

Agent hint: arrays require an explicit index — `arr.0.city` steps into `elementDef`, then `elementFields`.
