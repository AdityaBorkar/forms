# Concepts

You will name every moving part with the exact term from `docs/CONTEXT.md` so docs, code, and AI stay in sync.

## Canonical terms

| Term | Meaning |
|---|---|
| SchemaTree | The metadata tree an Adapter derives from a schema |
| FieldDef | One field's resolved metadata (Kind, optionality, constraints, nesting) |
| Kind | The single dispatch string on a FieldDef that selects a UI component |
| Adapter | The boundary that translates one validation library into a SchemaTree and a resolver |
| FieldComponentMap | The Kind-to-component table supplied once at factory time |
| SmartField | The component that resolves one dotted path and renders its mapped component |
| SmartFieldArray | The repeatable-rows wrapper around an array path |
| Form | The provider component that binds a FormInstance to React context |
| FormSystem | The closed factory result: Form, SmartField, SmartFieldArray, useForm, useFormContext |
| FieldMap | The SchemaTree carried in React context (`FormContextValue.fieldMap`) |

Never say `type`/`variant`/`widget` for Kind, `resolver`/`parser`/`bridge` for Adapter, or `field map` for FieldComponentMap — those collide (see `docs/CONTEXT.md`).

## How they connect

```
createFormSystem({ fieldComponents, schemaResolver }) → FormSystem
  useForm({ schema }) → SchemaTree + resolver (Adapter)
  <Form form>         → FormProvider + { fieldMap } context
  <SmartField name>   → resolveFieldDef → FieldComponentMap[Kind] via useController
  <SmartFieldArray>   → useFieldArray for repeatable rows
```

`FieldComponentMap` is closed over in the factory, not in context. `FormContextValue` carries only `{ fieldMap: SchemaTree }`. The raw schema is never touched downstream of the Adapter.
