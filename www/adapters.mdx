# Adapters

You will trace any SchemaTree claim back to the Adapter that produced it.

## Contract

```ts title="package/src/types.ts"
type SchemaAdapter<TSchema, TValues = unknown> = {
  createFieldMap(schema: TSchema): SchemaTree;
  createResolver(schema: TSchema): Resolver;
  readonly _infer?: TValues;
};
```

The Adapter is the only place that knows a validation library's internals. Both bundled Adapters are thin primitive sets over the shared `createFieldMapEngine` (`package/src/adapters/shared/index.ts:82-228`) behind an `AdapterPrimitives` boundary (`package/src/adapters/shared/index.ts:41-70`). Everything downstream operates on normalized output. Full internals live in `package/src/adapters/*/create-field-map.ts`.

## Zod

Walks private `schema._zod.def` via a `getZodDef` choke point (`package/src/adapters/zod/create-field-map.ts:32-34`) — intentionally fragile. 7 supported types (`package/src/adapters/zod/create-field-map.ts:21-29`):

`string`, `number`, `boolean`, `enum`, `array`, `object`, `date`.

| Input | Output |
|---|---|
| `z.string()` + `format`/`email`/`url` checks | `string` \| `email` \| `url` |
| `z.number()` + `greater_than`/`less_than` | `min`/`max` (inclusive) or `{ type: "gt"/"lt" }` checks (exclusive); `format` (e.g. `integer`) passes through |
| `z.enum()` | `enum` + `entries` |
| `z.array(el)` | `array` + `elementDef` (object-element children on `elementDef.elementFields`; array paths require an explicit index) |
| `z.object()` | `object` + recursive `elementFields` |
| `.optional()` | Recurses into `innerType` with `optional: true`; outer `meta` wins |
| `union` | Single non-`literal` branch wins, else throws (empty/all-literal/multi-branch) |
| `record`, bare `literal`, unknown | Throws `Unsupported Zod type: …`; never emits `kind: "unknown"` |

```ts title="app.ts"
import { zodAdapter } from "@adistack/forms/adapters/zod";
```

`createFieldMap`/`createResolver` are methods on `zodAdapter` (`package/src/adapters/zod/index.ts:14-20`); `createResolver` is also a standalone named export. `createResolver` is `zodResolver(schema)` from `@hookform/resolvers/zod`.

## Valibot

Walks public-ish `type`/`entries`/`item`/`wrapped`/`pipe` (`package/src/adapters/valibot/create-field-map.ts`). 8 supported types (`package/src/adapters/valibot/create-field-map.ts:37-46`):

`string`, `number`, `boolean`, `picklist`, `enum`, `array`, `object`, `date` (`picklist`/`enum` both normalize to `enum`).

| Input | Output |
|---|---|
| `v.string()` + `email`/`rfc_email`/`url` | `string` \| `email` \| `url` |
| Length (`min_length`/`max_length`/`length`/`non_empty`) | `min`/`max`/`checks` |
| `v.number()` + `min_value`/`max_value` | `min`/`max`; `gt_value`/`lt_value` → `{ type: "gt"/"lt" }`; `integer`/`safe_integer` → checks |
| `optional`/`nullish`/`exact_optional` | Force `optional: true` |
| `nullable` alone | Preserves outer optionality |
| Meta | `v.metadata()` merged plus `v.title()` → `label`/`title`, `v.description()` |
| `union`/`record`/unknown | Same policy as Zod — single non-`literal` wins, else throws |

```tsx title="examples/valibot-form.tsx"
v.pipe(v.string(), v.minLength(1), v.title("Full name"));
v.pipe(v.picklist(["admin", "member", "guest"]), v.title("Role"));
v.pipe(v.boolean(), v.title("Email notifications"));
```

Full schema in `examples/src/examples/valibot-form.tsx`. `createResolver` is `valibotResolver(schema)`.

## Defaults — intentionally absent

No auto-defaults are derived. `useForm({ defaultValues })` passes straight through to RHF; array rows use explicit `append(value)`.

Agent hint: Zod `SUPPORTED_TYPES` lives in `package/src/adapters/zod/create-field-map.ts:21-29`; Valibot adds `picklist` in `package/src/adapters/valibot/create-field-map.ts:37-46`, with `optional`/`nullish`/`exact_optional` forcing optional inline (`package/src/adapters/valibot/create-field-map.ts:247-273`).
